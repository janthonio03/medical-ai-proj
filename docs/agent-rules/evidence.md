# 검증·공개·인수인계

- `experiments/step*/`의 검증 실행본은 원래 바이트와 SHA256을 보존한다. 변경이 필요하면 검증할 새 버전으로 작업한다. `evidence/`에는 공개 가능한 검증 기록을 둔다. `scripts/`의 기존 KSC 분석은 CAST 실행·채점 경로와 별도로 다룬다.
- 실험 소스는 CPU 검사와 소스·processor·체크포인트 확인, 해당 GPU의 실제 보고서·로그 검토, 비교 타당성 검토를 마친 버전만 이 브랜치에 게시한다. CPU 전용 단계는 실제 CPU 실행 근거와 검증 범위를 기록한다. 진행 중에는 상태 문서를 갱신할 수 있다.
- 게시할 때 실행한 소스 SHA256 또는 커밋, 의존성·모델/LoRA·데이터/계획 식별자, 실제 dtype/backend, 수정 근거, 명령·GPU 수·Job ID, 결과·로그 경로와 검증 범위를 남긴다. 사용자 제공 콘솔과 독립 검토한 파일의 범위를 명시한다. ZIP을 검토할 때는 SHA256·CRC·manifest와 대상 멤버 해시를 확인한다.
- 공개 기록에서 모델 가중치, 원본 의료 영상·데이터·비공개 라벨, 토큰·비밀정보와 민감한 원본 로그를 제외한다. 소스의 라이선스와 출처를 보존한다.
- 검증된 단계마다 `README.md`에 현재 상태, `docs/CONTINUATION.md`에 재개 절차, `docs/EXPERIMENT_LOG.md`에 근거와 결정 이력을 갱신한다. 결과 분석 후 실제 완료 범위, 남은 비교·확인·실험, 전체 완료 여부와 이유, 다음 행동과 확인 방법을 기록하고 `docs/MASTER_PLAN.md`와 단계 기록에 반영한다.

공통 운영 규칙은 `docs/OPERATING_RULES.md`, 공개 전 검증 기준은 `README.md`의 GitHub governance 절을 따른다.
