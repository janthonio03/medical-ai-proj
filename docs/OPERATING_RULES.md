# 작업 및 인수인계 규칙

사용자 명시 지시: 2026-11-20 (Asia/Seoul). 이 규칙은 이후 채팅에서도 적용한다.

1. **GPU 제출 명령과 확인 명령을 함께 제공한다.** 진행 상태뿐 아니라 작업 완료 후 결과를 확인하는 전체 복사·붙여넣기 명령을 반드시 함께 제공한다. Job ID, Slurm 상태/종료 코드(조회 가능할 때), stdout/stderr, 보고서 위치, 통과/실패 검사, 완료/누락/실패 수를 확인할 수 있어야 한다. accounting 조회 불가와 실제 실패를 구분한다.
2. **검증된 단계마다 GitHub를 갱신한다.** 대상은 `janthonio03/medical-ai-proj`의 `paper_vs_open-source` 브랜치다. 코드를 작성하자마자 올리지 않는다. CPU 확인 및 해당 실험의 실제 GPU 결과와 로그를 검토하고, 목적에 맞는 정상 결과인지 확인하여 다음 단계로 넘어갈 때 검증된 소스와 문서를 기록한다. 기존 README의 상세 release gate를 함께 준수한다. 실패나 미검증 상태는 문서에 정확히 기록할 수 있지만 성공으로 표시하거나 미검증 실험 코드를 검증된 소스로 공개하지 않는다. 진단 실험의 성공은 검증 범위 내 발견을 뜻하며 전체 모델/성능 성공을 뜻하지 않는다.
3. **새 채팅은 GitHub만으로 이어갈 수 있어야 한다.** README는 목표와 현재 상태, `docs/CONTINUATION.md`는 다음 실행 단계와 재개 절차, `docs/EXPERIMENT_LOG.md`는 근거와 결정 이력을 유지한다. 각 검증된 단계에는 목적, 실행한 정확한 소스와 SHA/commit, 계획/모델/데이터 식별자, dtype/backend, 명령과 GPU 수, Job ID, 결과/로그 경로, 검사 결과, 해석의 한계, 실패·수정 이력, 보존할 산출물, 미해결 문제와 다음 명령을 남긴다. 서버에만 있는 파일과 GitHub에 실제 올라온 파일을 구분한다. 라이브 상태는 확인 시점을 명시한다.
4. **최대 동시 GPU 수는 4개다.** 오래 걸릴 것으로 판단되는 실행은 독립 샘플/조건/작업을 최대 4개 GPU로 병렬 처리할 수 있도록 구현한다. 완료 결과 재사용, 중복 작업 방지, 재개와 병합/검증을 지원하고 모든 동시 실행 합계가 4개를 넘지 않게 확인한다. 자원 상황과 작업 특성에 따라 실제 worker 수를 정하며, 단일 GPU가 필요한 작은 진단까지 무조건 4개를 쓰지는 않는다.
5. **사용자가 정한 실행시간 제한은 없다.** 시간 단축을 위해 실험 범위나 검증을 임의 축소하지 않는다. Slurm/QoS의 실제 walltime 제한은 별도로 준수하고, 긴 실행은 체크포인트/재개 또는 분할 실행으로 이어간다.
6. **위 규칙 자체도 이 브랜치에 보존한다.** 이후 변경 지시가 있으면 이 파일과 관련 인수인계 문서를 함께 갱신한다.

기존 Ariel 경로 규칙, ariel-v6..v12 제한, 공식 구조 최소 수정 원칙, 데이터/비밀정보 비공개 원칙과 함께 적용한다.
